# xdg-desktop-portal + input injection on Hyprland (gotchas)

- kdeconnect remote input on Wayland needs the portal interface org.freedesktop.portal.RemoteDesktop. Backends: portal-gnome (GNOME Shell), kde-plasma-portal (KWin), or the shim `hypr-kdeconnect-fix` (github.com/gfhdhytghd; packaged via kdeconnectRemoteInputOverlay in flake.nix). **xdg-desktop-portal-wlr and xdg-desktop-portal-hyprland do NOT implement RemoteDesktop** (hyprland's implements ScreenCast/Screenshot/GlobalShortcuts/InputCapture only).
- Remote input wiring lives in modules/desktop/hyprland-home.nix: portals.conf routing, .portal metadata + dbus service in XDG_DATA_HOME, systemd user unit Type=dbus (D-Bus activation via dbus-broker). The unit must NOT start before the graphical session: the shim reads WAYLAND_DISPLAY lazily via getenv at session creation; activation happens on demand, after hyprland imports env into systemd --user.
- **App id trap**: xdg-desktop-portal assigns app ids to host processes ONLY from the caller's systemd user unit name (must match `app-<id>-autostart.service` / `app-<id>-<rand>.scope`) AND the `<id>.desktop` file must exist in XDG_DATA_DIRS. A daemon started by hyprland exec-once has no unit → app id "" → the shim refuses ("refusing RemoteDesktop session for app id ''"; its fallback only accepts /usr/bin|/usr/lib|/usr/libexec/kdeconnectd, impossible on NixOS). FIX: kdeconnectd runs as systemd user unit named `app-org.kde.kdeconnect.daemon-autostart` (parses to app id org.kde.kdeconnect.daemon; org.kde.kdeconnect.daemon.desktop ships with kdeconnect-kde). Do NOT start kdeconnectd from hyprland exec-once.
- kdeconnectd's Qt Wayland window class (e.g. presenter) = applicationName "kdeconnect.daemon" (KAboutData componentName), NOT org.kde.kdeconnect — window rules must match `org.kde.kdeconnect|kdeconnect.daemon`.
- New Hyprland (lua config era): `hyprctl rules` no longer exists; use `hyprctl configerrors` + `hyprctl clients`.
- Verify app-id flow without phone: `systemd-run --user --scope --unit=app-org.kde.kdeconnect.daemon-autostart dbus-send --session --dest=org.freedesktop.portal.Desktop /org/freedesktop/portal/desktop org.freedesktop.portal.RemoteDesktop.CreateSession "dict:string:variant:session_handle_token,string:testtoken1,handle_token,string:testtoken2"` (tokens must be alphanumeric) then check journal for the shim's refusal log.
- Live session debugging: `busctl --user list | grep -i kdeconnect` (kdeconnectd binary shows as `.kdeconnectd-wr`, so `pkill -x kdeconnectd` does NOT match it — use `kill <pid>`).
- After changing portal metadata/portals.conf: `systemctl --user restart xdg-desktop-portal` (or relogin). Verify: `busctl --user introspect org.freedesktop.portal.Desktop /org/freedesktop/portal/desktop org.freedesktop.portal.RemoteDesktop`.
- Self-test: `hypr-kdeconnect-portal --self-test-motion 120 0` moves the cursor in the live session (checks Hyprland exposes zwlr_virtual_pointer/zwp_virtual_keyboard).
- hypr-kdeconnect-fix: C++23 cmake build; needs wayland-scanner as SEPARATE nixpkgs package (wayland package no longer ships it, `scanner=false` flag), libeis comes from nixpkgs `libei` (provides libeis-1.0.pc). qt daemon: set dontWrapQtApps=true.
- Hyprland blur: presenter window of kdeconnect (fullscreen transparent QQuickView, class org.kde.kdeconnect) looks opaque/frosted with blur enabled (ignore_opacity=true) — window rule no_blur fixes it. Pattern: other blur-exempt apps (steam/mpv/wezterm) use no_blur + opacity "1 override".
- Remote input via X11/XTest (kdeconnectd with QT_QPA_PLATFORM=xcb) does NOT work on Hyprland: Xwayland only forwards XTEST to compositors with libei (EI) support; Hyprland has none → events dropped.
